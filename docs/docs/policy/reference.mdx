## Limits

The stateful limits of a session (SHIELD §6.3).

Three count the harness's actions; two count what its model costs: the
**model budget** in tokens and the **spend** in credits (the deployment's
spend limit; 100 credits are one USD). Each has a soft threshold, where the
next call asks the person, and a hard one, where each further call is
refused and the sentence says what would let it go on.

| Field | Type | Required | What it says |
|---|---|---|---|
| `bytes_written` | Threshold or null | no | Bytes written to the workspace. |
| `model_tokens` | Threshold or null | no | The model budget: tokens the session's model requests spend, in and out. |
| `spend` | Threshold or null | no | The spend limit: credits the session spends on models (100 credits a USD). |
| `terminals_open` | Threshold or null | no | Terminals open at once. |
| `tool_calls` | Threshold or null | no | Classed actions per session. |

## The classes and the kinds

Every action is classed as one of `read`, `write`, `send`, `buy`, `delete`, `execute` (F-10); ACP's tool kinds are `read`, `edit`, `delete`, `move`, `search`, `execute`, `think`, `fetch`, `switch_mode`, `other`, and `other` fails closed to `write`.

## Soft and hard limits

A `Threshold` has a `soft` count, where the next call asks the person once, and a `hard` count, where each further call is refused and the sentence says what would let the session go on. The limits are stateful per session; the strictest scope's decides first.
