# Protocols

The Shield speaks the **Agent Client Protocol** (ACP, protocol version 1) on both faces: an ACP agent towards the client, an ACP client towards the agent it launched, on the official `agent-client-protocol` SDK. `session/update` is normalised into the package's own events (text, thought, tool call, plan, commands, mode, permission, question); a malformed update ends the turn with a sentence.

What the Shield lends an agent: the MCP servers the policy's `mcp.allow` names, in `session/new`; nothing else. What it answers itself: `fs/read_text_file`, `fs/write_text_file`, `terminal/*`, each a decided and recorded action the client sees as a tool row.

Over the wire, `agent-shield serve` speaks the two transports the ecosystem's bridges use — WebSocket (one JSON-RPC message per text frame) and ACP Streamable HTTP (`POST /acp` in, SSE streams out, `Acp-Connection-Id` and `Acp-Session-Id` headers) — as [serve and registration](../serve/) describes.

**Built:** ACP on both faces over stdio, WebSocket and Streamable HTTP. **Not built:** the A2A, AG-UI and other faces of the Shield are Datalayer's runtimes', not this package's.
