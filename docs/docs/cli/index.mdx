# CLI Reference

Agent Shield has a command-line interface built with
[Typer](https://typer.tiangolo.com/), for two kinds of team:

- **teams on Datalayer** — the catalogued teams, run on the platform's
  orchestration control plane: list and show them, start one on a goal, follow
  its run seat by seat, steer, pause, resume, cancel or terminate it;
- **a self-hosted server's teams** — the teams an `agent-shield serve` server
  holds, under `agent-shield local`.

## Installation

```bash
pip install "agent-shield[datalayer]"
```

The `datalayer` extra brings Datalayer core, which the commands for teams on
Datalayer run on; without it, only `serve` and `local` are there. The entry
point is `agent-shield`:

```bash
agent-shield --help
```

### In the Datalayer CLI

agent-shield is a [reactor](https://reactor.datalayer.tech/python-plugins/cli)
extension of the Datalayer CLI: installed beside it, the same commands are
`datalayer agent-shield …` — and `reactor agent-shield …` beside the `reactor`
command. Nothing needs configuring; the package advertises itself under the
`datalayer.cli` and `datalayer.reactor.cli` entry point groups.

```bash
datalayer agent-shield runs notebook-benchmark
```

## Teams on Datalayer

A run of a team is one root execution on the orchestration control plane: the
supervisor answers it, and each seat the team schedules is a child execution
under it. These commands name a team by its id and a run by its root
execution, and act on the whole tree through the same implementation as
`datalayer executions`. They sign in as the Datalayer CLI does.

| Command | What it does |
|---------|--------------|
| `list [--prefix …]` | The catalogued teams: id, name, mode (`sequential`, `parallel`, `supervisor`) and how many seats |
| `show <team>` | Its supervisor and its seats in order: name, role, what each waits on, its goal |
| `start <team> --goal … [--instructions …] [--criterion …] [--deadline …] [--watch]` | Start a run: the team's root execution, delegated the way a benchmark's team task is. `--watch` follows it until it is over |
| `runs [<team>] [--active] [-n 20]` | A team's runs (every team's without one), latest first |
| `status <run>` | The run's tree, seat by seat: status, attempts, when it last moved, and any error |
| `monitor <run>` | Stream every event of the run's tree until every execution in it is over |
| `steer <run> "<instructions>"` | Add instructions while the team works |
| `pause <run> [--reason …]` / `resume <run> [--checkpoint …]` | Stop at the next checkpoint without losing anything, and go on |
| `cancel <run> [--no-cascade]` | Stop the run and, by default, every seat under it; its history is kept |
| `terminate <run> [--keep-worker]` | End the run for good and release its workers |
| `artifacts <run>` | What the run produced, with every seat's by default |

Every command takes `--account` to act in an organization and `-o json` for a
machine-readable answer. A mutating command derives its idempotency key from
what it asks, so running the same `start` twice is the same run; pass
`--idempotency-key` to start another. `list` and `show` read the team catalogue
that ships with agent-runtimes.

```bash
agent-shield show notebook-benchmark
agent-shield start notebook-benchmark --goal "Profile customers.csv and report the duplicates" --watch
agent-shield runs notebook-benchmark --active
agent-shield status exec_5b8da50a4c83498d86a0b308bfb94909
agent-shield pause exec_5b8da50a4c83498d86a0b308bfb94909 --reason "Waiting for the data owner"
```

## The demo team

The landing's anonymous page shows a team of two applications, the agentspecs
team `sales-and-accounting`: **Sales** runs in the visitor's browser, and
**Accounting** (the `accounting` application: the `worker-accountant` agent,
the `odoo-accounting` MCP server, read only) runs in the cloud. `demo` puts the
members that run in the cloud on Datalayer, under your own account:

```bash
pip install "agent-shield[demo]"
```

The `demo` extra brings agent-runtimes and agentspecs: the team and
application specs, and the client that reserves the runtime. You are the
person the `datalayer` CLI signs in as: `datalayer login`, or
`DATALAYER_API_KEY`.

| Command | What it does |
|---------|--------------|
| `demo deploy [--dry-run] [-e <environment>] [-m 1..480] [-o json]` | Each member whose `runs_in` is `runtime` gets a cloud runtime of yours, named `agent-shield-demo-<team>-<member>`, configured with its application served over A2A and open to visitors. Prints the A2A address, the agent card and the landing setting (`demoTeam.accountingA2AUrl`) to set. Run again, it reuses the runtime it finds by that name. `--dry-run` says what would be launched and configured, and what it would cost at most, and launches nothing |
| `demo status [-o json]` | Each member: where it runs, how it stands (`serving`, `not deployed`, …), its A2A address, its runtime and the time left (`never` for an unmetered runtime) |
| `demo url [--member accounting]` | Only the A2A address, for scripts; fails when the member is not deployed or not serving |
| `demo stop` | Stops the team's demo runtimes |

Every command takes `--team` for another team spec. A deploy refuses before
launching anything when nobody is signed in, when Datalayer does not list
your runtimes (a failed listing is never read as nothing deployed, which
would launch a second runtime of the same name), when the credits left cannot
cover the reservation, or when Datalayer refuses the launch. `--minutes` is
between 1 and 480, the platform's maximum. A runtime it launched is stopped
again when anything after the launch fails: it does not come up, it does not
take the application, or the runtime times out, refuses the connection or
answers something that is not JSON.

### A demo that never ends: `DATALAYER_MAGIC_API_KEY`

With `DATALAYER_MAGIC_API_KEY` set in the environment (the platform's magic
key, a secret), agent-runtimes' client sends it with the runtime it creates
and Datalayer starts the runtime **unmetered**: it consumes no credits and
never expires. The deploy then asks for no credits, a `--dry-run` says
`unmetered: yes` (and `"unmetered": true` in JSON), the deploy says the
runtime never expires, and `status` shows `never` for the time left. The key
is never printed. Unset, nothing is sent and the runtime is metered as above.
`--minutes` is still validated and sent; Datalayer ignores it for a runtime
that never expires.

If the services do not take the key yet, Datalayer launches the runtime
metered; the deploy stops it and says so, rather than leave it charging.

```bash
export DATALAYER_MAGIC_API_KEY=…      # from the platform's rc; never commit it
datalayer agent-shield demo deploy --dry-run   # unmetered: yes
datalayer agent-shield demo deploy
```

```bash
datalayer agent-shield demo deploy --dry-run
datalayer agent-shield demo deploy
datalayer agent-shield demo status
datalayer agent-shield demo url
datalayer agent-shield demo stop
```

## A self-hosted server

The commands for a self-hosted agent-shield server — `serve` it, then create,
start and task the teams it holds — talk to its REST API. Everything but
`serve` is under `local`.

### `serve`

Start the Agent Shield API server.

```bash
agent-shield serve [OPTIONS]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--host` | `0.0.0.0` | Host to bind to |
| `--port` | `8765` | Port to listen on |
| `--reload` | `false` | Enable auto-reload for development |

**Example:**

```bash
agent-shield serve --port 9000 --reload
```

---

### `local create`

Create a new team from a YAML or JSON configuration file.

```bash
agent-shield local create CONFIG_PATH [OPTIONS]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--server` | `http://localhost:8765` | Server URL |

**Example:**

```bash
agent-shield local create team.yaml
agent-shield local create config.json --server http://myserver:9000
```

**Config file format (YAML):**

```yaml
name: research-team
execution_mode: parallel
members:
  - name: researcher
    model: openai:gpt-4o
    system_prompt: You are a research analyst.
  - name: writer
    model: anthropic:claude-sonnet-4-20250514
    system_prompt: You are a technical writer.
supervisor:
  member_name: researcher
  review_required: true
```

```bash

```

```bash

```

### `local resume`

```bash

```

---

### `local delete`

Delete a team. The team must be stopped first (or use `--force`).

```bash
agent-shield local delete TEAM_ID [OPTIONS]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--force` | `false` | Force deletion even if running |
| `--server` | `http://localhost:8765` | Server URL |

---

### `local assign`

Assign a task to a team.

```bash
agent-shield local assign TEAM_ID DESCRIPTION [OPTIONS]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--priority` | `medium` | Task priority (`low`, `medium`, `high`, `critical`) |
| `--assigned-to` | | Assign to a specific member |
| `--server` | `http://localhost:8765` | Server URL |

**Example:**

```bash
agent-shield local assign abc123 "Analyse Q4 revenue trends" --priority high
agent-shield local assign abc123 "Write summary" --assigned-to writer
```

---

### `local metrics`

Show team metrics (tasks completed, failed, active members, etc.).

```bash
agent-shield local metrics TEAM_ID [OPTIONS]
```

---

### `local events`

Show recent team events.

```bash
agent-shield local events TEAM_ID [OPTIONS]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--limit` | `50` | Maximum number of events to show |
| `--server` | `http://localhost:8765` | Server URL |

### Typical workflow

```bash
# 1. Start the server
agent-shield serve &

# 2. Create a team
agent-shield local create team.yaml
# Output: Created team: abc-123-def

# 3. Start the team
agent-shield local start abc-123-def

# 4. Assign tasks
agent-shield local assign abc-123-def "Research recent AI papers" --priority high
agent-shield local assign abc-123-def "Write executive summary"

# 5. Monitor progress
agent-shield local status abc-123-def
agent-shield local metrics abc-123-def
agent-shield local events abc-123-def

# 6. Clean up
agent-shield local stop abc-123-def
agent-shield local delete abc-123-def
```
