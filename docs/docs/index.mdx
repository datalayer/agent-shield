# 🤖 🛡️ Agent Shield

**A runtime firewall for every agent.** Deploy a shield with each agent. Enforce permissions before actions execute, manage policies centrally, and retain an audit trail.

`agent-shield run -- <command>` starts any [Agent Client Protocol](https://agentclientprotocol.com) agent — Claude Code, Codex, Gemini CLI, Goose, OpenCode, OpenHands, or one of your own — as its subprocess and stands as an ACP agent in front of it. Any ACP client sees one agent; in between, the Shield decides, confines and records: `session/request_permission` by the policy (*do it* answered without the client, *ask me first* forwarded with the same options, *leave it to me* refused in a sentence), the agent's tool calls classed and held to the limits, `fs/*` and `terminal/*` confined to the workspace, `mcpServers` cut to what the policy lends, every action written to the audit and exported over OTEL.

`agent-shield serve` is the same proxy as a server, over WebSocket and ACP Streamable HTTP, one harness per connection, for the clients that reach an agent at an address — editors, notebooks, messaging bridges, a mobile app — and for a Shield on your own infrastructure, registered with Datalayer for its policies and its observability.

## The first five minutes

```bash
pip install "datalayer-agent-shield[claude-code]"
agent-shield setup                       # node, the vendor CLIs, the credentials by name; the pinned adapter into the Shield's own prefix
agent-shield run -- claude-agent-acp     # Claude Code behind the Shield, on this directory, with the default policy
```

The first decision is seen in the terminal with the first tool call. `agent-shield log` shows the audit; `agent-shield policy show` the policy in force and where each line came from. Measured on 15 October 2026 from a clean prefix: `setup` 27 seconds, `run` to a session 1.5 seconds.

On Datalayer, the same Shield stands beside every application a Maker ships, managed from the SaaS — read [The Shield](https://datalayer.ai/docs/shield) and its pages for the people who build and administer: [organization rules](https://datalayer.ai/docs/shield/policies), [what it sees and records](https://datalayer.ai/docs/shield/observability), [conformance](https://datalayer.ai/docs/shield/conformance) and [the report](https://datalayer.ai/docs/shield/report), [a Rule and a permission](https://datalayer.ai/docs/shield/authorization), [your companies](https://datalayer.ai/docs/shield/pap), [your own infrastructure](https://datalayer.ai/docs/shield/your-infrastructure). Runnable examples — the proxy driven from Python, a coding agent on Datalayer's runtime, a rule on a running session, the audit read back, an orchestrator reading a diff over A2A — are in agent-runtimes' [`examples/shield`](https://github.com/datalayer/agent-runtimes/tree/main/examples/shield).

**Built:** the proxy (`run`), the server (`serve`, `connect`), the policy engine with its three levels and its limits, the register, the audit and the OTEL export, registration with Datalayer (`setup --register`), the TypeScript package (types, sentences, displays, the report renderer). **Not built:** the long tail of ACP agents beyond the register (SHIELD SH-57), PAP lent to a standalone Shield (SH-72), the Shield report in Datalayer's Validate tab (SH-36).
